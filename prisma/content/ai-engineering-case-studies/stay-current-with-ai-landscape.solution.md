**Show a system, not a list of newsletters.**

1. **Anchor on fundamentals** (attention/Transformers, retrieval, evaluation, distributed systems, statistics). New tools are variations on a few durable ideas, so they become easier to absorb.
2. **Curated inputs (about 3 to 5 hours a week):**
   - Primary sources: **arXiv** (cs.CL, cs.LG) via a digest, **Hugging Face Papers**, model release notes and system cards, provider docs/changelogs.
   - Practitioner voices: engineering blogs, talks (AI Engineer, NeurIPS/ICLR recordings), newsletters (The Batch, Latent Space, Import AI), selected researchers and builders on X/LinkedIn, GitHub trending and release feeds for key libraries (vLLM, LangGraph, PEFT).
3. **Build to learn:** reproduce a paper at small scale, try a new model or technique on my own eval set, ship side projects; keep a notebook of experiments with results.
4. **Filter hype:** ask what problem it solves, what the benchmark really measures (contamination, saturation), whether there is code and independent replication, and whether it beats a strong simple baseline for **my** use case.
5. **Evaluate against my tasks:** maintain a personal eval set so every new model gets a quick, comparable test.
6. **Community and teaching:** discussion groups, open-source contributions, writing short posts or internal talks; explaining forces understanding.
7. **Prioritise:** deep on a few areas (RAG, evaluation, agents) and shallow awareness elsewhere; revisit quarterly.
