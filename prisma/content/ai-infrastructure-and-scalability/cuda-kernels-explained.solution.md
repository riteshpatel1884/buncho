A **CUDA kernel** is a function that runs on the GPU, executed by many threads in parallel. The host (CPU) launches it with a **grid of thread blocks**.

**Hierarchy:** grid → blocks → threads (grouped into warps of 32). Each thread knows `threadIdx`, `blockIdx`, `blockDim` and computes its own data index.

```cpp
__global__ void add(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;     // global element index
    if (i < n) c[i] = a[i] + b[i];
}
// host: add<<<(n + 255) / 256, 256>>>(d_a, d_b, d_c, n);
```

**Execution:** blocks are assigned to SMs; warps execute in lock-step (SIMT). Divergent branches inside a warp are serialised; many resident warps hide memory latency (**occupancy**).

**Performance essentials**

- **Memory coalescing:** consecutive threads should access consecutive addresses so a warp's loads merge into few transactions.
- **Shared memory tiling:** for matmul, each block loads tiles of A and B into fast on-chip shared memory, synchronises (`__syncthreads()`), and reuses them many times, turning O(n) global reads per output into O(n/tile).
- **Registers and occupancy trade-off,** bank conflicts in shared memory, avoiding divergence.
- **Tensor cores** via WMMA/MMA instructions or libraries; **async copies** and pipelining (Hopper TMA).
- **Kernel fusion:** combine elementwise ops (bias + GELU + dropout) to avoid writing intermediates to HBM; **CUDA graphs** cut launch overhead for many small kernels.

**How deep learning uses them:** PyTorch ops dispatch to precompiled kernels (cuBLAS, cuDNN, CUTLASS, FlashAttention). Custom kernels are written in CUDA C++, **Triton** (Python-like, block-level), or generated by `torch.compile`/XLA. Streams allow concurrent kernels and copies; launches are asynchronous, so profile with Nsight Systems/Compute or `torch.profiler` and synchronise only when needed.

**Mental model:** think in terms of data movement; most LLM kernels are bandwidth-limited, so the win comes from moving fewer bytes.
